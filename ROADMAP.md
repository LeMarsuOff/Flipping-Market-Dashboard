- [x] **Mapping reverts to template default on profil re-sync — auto-template-map was re-writing defaults whenever the override set read empty + screenshot auto-map ignored user picks** (2026-06-01) — Suite du fix cross-device de la veille : un membre (sur code à jour, sa propre base) signalait que le bug revenait **lors d'un re-sync du profil** (bouton `↻` Sync ou Full resync). Investigation : le re-sync passe par `_loadNotionTrades` qui ne re-tire PAS le cloud (`syncFromRemote` absent du chemin) — donc le revert venait des deux auto-mappers internes lancés à chaque sync. **Deux causes distinctes, deux verrous.** **(1) Garde anti-revert dans `_maybeAutoApplyTemplateMapping`** ([dashboard.js](dashboard.js) ~8598) : la fonction n'écrit les défauts template QUE si le set d'overrides se lit **vide**. Sur un profil déjà synchronisé, un set vide est anormal (la perso devrait être là) — quelle qu'en soit la cause transitoire (cloud `{}`, wipe LS, race de contexte), écrire les défauts cimentait le revert (RR Max → `RR Max`, toutes les dims non-screenshot → défaut). Nouvelle règle : **jamais d'écriture automatique de défauts sur un profil ayant déjà sync** (`profile.notionLastSync || notionTradeCount>0 || notionSyncState==='synced'`) ; on décline l'écriture et on garde le set en l'état. Nouveau param `opts.forceWrite` ajouté à la signature : le bouton "Reapply template defaults" ([dashboard.js](dashboard.js) ~9103) le passe à `true` pour rester le seul chemin sanctionné de re-seed à la demande. Un `console.warn('[MappingRevert] blocked…')` se déclenche uniquement quand la garde bloque (silencieux pour les users normaux). **(2) Appartenance utilisateur dans `_autoMapScreenshotsByRawKeys`** ([dashboard.js](dashboard.js) ~8770) : l'auto-map screenshot (lancé à chaque sync ET sur le reload post-sync via [dashboard.js:7434](dashboard.js:7434)) appliquait sa règle "F&M gagne" **sans jamais consulter** le set d'appartenance `flipping_auto_mapped_dims_v1` → il ré-écrasait des overrides screenshot que l'utilisateur avait explicitement pencil-pickés (symptôme : screenshots se remappent / se dédoublent au re-sync). Fix : lecture de `_getAutoMappedDims()` avant la boucle + skip de tout dim `present mais PAS auto-mappé` (= choix user authoritaire). Les dims encore auto-mappées restent éligibles à la dérivation (first-connect + upgrade URL→F&M intacts). **Validé en preview** (port 8000, v=854, 0 erreur console) via tests stubbés : profil établi + overrides vides → **bloqué** (set reste vide) ✓ ; first-connect → écrit la baseline ✓ ; `forceWrite` (Reapply) → écrit les défauts ✓ ; override user présent → court-circuit préserve ✓ ; screenshot choisi par user → préservé ✓ ; screenshot auto-mappé → re-dérivé ✓. **Effet** : un re-sync (incrémental ou full) ne peut plus réinitialiser le mapping aux défauts, même si le cloud est encore corrompu. Le membre re-saisit son mapping une fois (le fix cross-device l'envoie au cloud) et plus aucun sync ne le casse. Cache JS `?v=846 → 854`.
